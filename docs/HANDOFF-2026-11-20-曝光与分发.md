## 3. 分发路径的关键决策

**npm 从「前置门槛」降级为「后补」。** 注册被风控阻断，而 awesome 的贡献指南明确写了
「收录与是否发布 npm 无关」。因此 0.2.2 把 GitHub 变为一等公民：

1. `prepare` → `prepack`（只影响安装期是否跑脚本，不改分析能力）；
2. 每个 Release 附预构建 tarball，文件名**不带版本号**（`latest/download/` 按字面取文件名）；
3. README / 插件文档 / 交接全部改写到 `github:` 形式，npm 恢复后只需改回一行命令。

被放弃的方案与原因：[曝光规划 §1](旧文档/11月20日/2026-11-20-dsh-archmap-explorer-曝光规划.md)
里的表格仍把 npm 当硬门槛，以本交接为准。

## 6. 版本判断：不发 0.2.3

`git diff dsh-plugin-v0.2.2..HEAD` 只动了 `.github/`、`demo-site/`、`docs/` 和 README，没有触碰
`lib/`、`archmap/`、`scripts/`、`package.json`。发行物行为完全一致，为一个未变的包再发一个
标签只会稀释发布记录。

**下次该发 0.2.3 的时机**：英文 UI 落地，或 P1-1（属性链 / Protocol 解析）修完——两者都会
改变用户可感知的行为，届时一并更新 tarball 与目录条目。若 npm 先恢复，也可以只把当前 0.2.2
发布到 npm，以解锁 Discover 索引，不必改版本行为。
（`tarball` 用的是 `latest/download/`，换版本不需要改条目。）

## 8. 接手第一件事

```bash
# 1) 本地基线
python3 -m pytest -q
npm test
python3 -m archmap build . --config examples/archmap_v3.archmap.json --out .archmap/self
python3 -m archmap check .archmap/self/architecture.json

# 2) 验证两条安装链路（使用临时 profile，测完可删）
dsh plugin --profile archmap-check add github:MerlinSassoon/dsh-archmap-explorer
dsh --profile archmap-check --dump-config | grep -A2 'dsh-archmap-explorer'

dsh plugin --profile archmap-check-tgz add \
  https://github.com/MerlinSassoon/dsh-archmap-explorer/releases/latest/download/dsh-archmap-explorer.tgz

# 3) 检查目录页和索引边界
curl -I https://awesome-dsh-plugin.com/p/MerlinSassoon/dsh-archmap-explorer/
```
