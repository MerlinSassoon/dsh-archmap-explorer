## 1. npm 首发（约 5 分钟）

当前环境有一个必须先处理的坑：`~/.npmrc` 指向 `registry.npmmirror.com`（镜像只读，无法发布），且未登录（`ENEEDAUTH`）。

```bash
# 1) 登录官方 registry（会走浏览器或一次性的 2FA）
npm login --registry=https://registry.npmjs.org

# 2) 确认身份
npm whoami --registry=https://registry.npmjs.org

# 3) 发布 0.2.1（与已有 git 标签 dsh-plugin-v0.2.1 对齐）
npm publish --registry=https://registry.npmjs.org --access public

# 4) 验证
npm view dsh-archmap-explorer version --registry=https://registry.npmjs.org
```

发布后立刻把两处安装命令换成 npm 形态：

- `README.md` → DSH plugin 段：`dsh plugin add dsh-archmap-explorer`
- `README.zh.md` → 同一段：`dsh plugin add dsh-archmap-explorer`，并删掉“尚未发布到 npm”的括注
- 顺带在 README 顶部加 npm 版本徽章：
  `[![npm](https://img.shields.io/npm/v/dsh-archmap-explorer?style=flat-square)](https://www.npmjs.com/package/dsh-archmap-explorer)`

干净 profile 验证（换一个 profile 名，避免受现有安装影响）：

```bash
dsh plugin --profile npmcheck add dsh-archmap-explorer
dsh --profile npmcheck --dump-config | grep tool-archmap
dsh plugin --profile npmcheck list
```

判据：不出现 pnpm `onlyBuiltDependencies` 手工步骤，一次装成功。

## 6. 官方 Discussions 发帖（约 10 分钟）

仓库：`https://github.com/deepseek-ai/deepseek-harness/discussions`，分区名以页面实际为准（找 community / showcase 类分区）。

标题：

```text
ArchMap：把 Python 项目变成可逐层下钻的架构图（插件 dsh-archmap-explorer）
```

正文（中文，先问题后产物）：

```markdown
接一个陌生 Python 仓库时，我的流程一直是：读 README → 翻目录 → grep 入口 → 在脑子里拼图。
让模型描述架构，得到的是一段无法验证的散文：它说得很有道理，但我没法核对。

ArchMap 做的是另一件事：静态解析源码，生成一个自包含的 architecture.html，四层可下钻。

- 项目页：一条执行流卡片 + 每个能力模块一张卡片
- 执行流页：入口函数的控制骨架，分支/循环/返回/dispatch 都有边界
- 模块页：Provider、能力面、类与类型关系
- 方法页：源码切片 + callers/callees；解析不到的调用单独标出来，不混进"确定关系"

在 DSH 里它是 bundle 插件，注册 4 个工具：
archmap_build / archmap_annotate / archmap_query / archmap_guide，另带两个 skill。
模型的职责只有语义注解；nodeId、sourceHash 和注解是否过期全部由 Python 校验。

免安装试玩（真实项目，直接打开）：<demo 链接>
安装：dsh plugin add dsh-archmap-explorer

已知限制写清楚了：静态解析覆盖不到动态分发；callers=0 有可能表示"没解析到"而不是"没有调用者"，
这种情况我会标 unresolved 而不是给一个假答案。

欢迎拿真实项目试，尤其是"图不对"的反馈 —— 这类反馈最有价值。
```

英文版用于 HN/Reddit 时再按 §7 改。

```text
Author here. I built this after inheriting a 30k-line Python service where every
attempt to draw the architecture turned into a hand-maintained diagram that rotted.

ArchMap parses with ast, projects project → execution flow → module → method, and
writes a single self-contained HTML (no CDN, no fonts, opens from file://).
The model can write semantic notes, but node ids and source hashes are validated
in Python, so annotations can't drift silently.

What it is not: a runtime tracer, and it won't guess dynamic dispatch — unresolved
calls are labeled instead of being drawn as facts.

Demo: <link>. Happy to answer anything about the projection model or the
unresolved-call contract.
```
