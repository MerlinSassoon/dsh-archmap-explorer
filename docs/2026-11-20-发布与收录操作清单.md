正文（中文，先问题后产物）：

```markdown
接一个陌生 Python 仓库时，我的流程一直是：读 README → 翻目录 → grep 入口 → 在脑子里拼图。
让模型描述架构，得到的是一段无法验证的散文：它说得很有道理，但我没法核对。

ArchMap 做的是另一件事：静态解析源码，生成一个自包含的 architecture.html，四层可下钻。

- 项目页：一条执行流卡片 + 每个能力模块一张卡片
- 执行流页：入口函数的控制骨架，分支/循环/返回/dispatch 都有边界
- 模块页：Provider、能力面、类与类型关系
- 方法页：源码切片 + callers/callees；解析不到的调用单独标出来，不混进"确定关系"

在 DSH 里它是 bundle 插件，注册 4 个工具：
archmap_build / archmap_annotate / archmap_query / archmap_guide，另带两个 skill。
模型的职责只有语义注解；nodeId、sourceHash 和注解是否过期全部由 Python 校验。

免安装试玩（真实项目，直接打开）：<demo 链接>
安装：dsh plugin add dsh-archmap-explorer

已知限制写清楚了：静态解析覆盖不到动态分发；callers=0 有可能表示"没解析到"而不是"没有调用者"，
这种情况我会标 unresolved 而不是给一个假答案。

欢迎拿真实项目试，尤其是"图不对"的反馈 —— 这类反馈最有价值。
```

英文版用于 HN/Reddit 时再按 §7 改。

英文版（发在英文分区，或给 dsh-market / HN 复用开头）：

```markdown
**ArchMap — static, drillable architecture maps for Python**

Reading an unfamiliar Python repo is usually: skim the README, list the
directories, grep for the entry point, then assemble the picture in your head.
Asking a model for the architecture gets you prose you cannot verify.

ArchMap parses the source and writes one self-contained HTML you can drill:
project -> execution flow -> module surface -> method source and callers.
Nothing runs, nothing is fetched, the file opens from disk.

In DSH it is a bundle plugin with four tools (archmap_build, archmap_annotate,
archmap_query, archmap_guide) and two skills. The model only writes semantic
notes; node ids, source hashes and staleness are validated in Python.

Demo (no install): https://merlinsassoon.github.io/dsh-archmap-explorer/
Install: dsh plugin add dsh-archmap-explorer

Known limits are documented: dynamic dispatch is not guessed, and a `callers`
count of zero can mean "not resolved" — that case is labeled, not hidden.
```
