# P5.1 执行流项目节点样式

> 状态：已实现。本文是执行流卡片的当前视觉规范；HTML 基准样例见
> [`prototype/p5.1-execution-cards-preview.html`](../prototype/p5.1-execution-cards-preview.html)。

## 1. 设计目标

执行流卡片采用“项目节点”样式：

- 卡片是真实语义节点，不展示虚假的函数签名或运行时输入框。
- 端口是卡片内部的一等行元素，不使用绝对定位圆点挂件。
- 端口行不包裹方框、不使用独立背景色。
- 左列承载进入/分支入口，右列承载离开、分支与分发端口。
- 流程文字和端口标签全部位于卡片内部。
- 汇合不是节点：多条路径直接进入同一个真实后继节点或 `exit`。

## 2. 卡片结构

```text
.execution-node.kind-<kind>
├── .exec-node-header
│   ├── .exec-node-icon
│   ├── .exec-node-kind
│   └── .exec-node-module
└── .exec-node-body
    ├── .exec-copy
    │   ├── .exec-node-label
    │   ├── .exec-node-note（可选，人类备注）
    │   └── .exec-node-meta
    ├── .exec-port-grid
    │   ├── .exec-port-side.is-left
    │   │   └── .exec-port-item[data-port]
    │   └── .exec-port-side.is-right
    │       └── .exec-port-item[data-port]
    └── .exec-foot（可选，loop / dispatch 元信息）
```

### 2.1 卡片外壳

- 圆角 `13px`，深色卡片主体，顶部彩色标题栏。
- 标题栏颜色沿用模块颜色 `--mc` / `--mc-rgb`。
- 标题栏固定高度 `34px`，包含图标、节点类型和模块名。
- 卡片宽度由布局层决定，生产尺寸约为 `250–300px`。
- 卡片内容溢出隐藏，不用绝对定位端口。

### 2.2 端口行

- 端口由 `.exec-port-item` 表达，使用 flex 行内布局。
- 端口符号使用 `.exec-port-symbol`：
  - `triangle`：流程进入/离开；
  - `circle`：分支、候选；
  - `diamond`：默认分支。
- 端口左侧/右侧短引导线由 `::before` 生成并连接卡片边缘。
- 端口行本身没有边框、背景、圆角或独立卡片感。
- 端口颜色只表达语义，文字标签始终存在：
  - 进入/离开：浅灰；
  - 是：绿色；
  - 否：红色；
  - case：蓝色；
  - default：灰色；
  - loop body：青色；
  - loop complete：浅灰；
  - dispatch 候选：紫色。

## 3. 节点目录与端口

| kind | 展示名 | 端口 | 说明 |
|---|---|---|---|
| `entry` | 入口 | `out` | 执行起点，右列“开始” |
| `exit` | 结束 | `in` | 按需生成的结束锚点；仅承接真实到达的隐式结束路径 |
| `free_function` | 本地调用 | `in / out` | 主模块自由函数或类方法原子步骤，`callableKind` 区分 |
| `interface` | 功能接口 | `in / out` | 功能模块 capability 边界 |
| `dispatch` | 动态分发 | `in / out` | 候选原子化，卡片底部显示候选状态 |
| `branch` | 双分支 | `in / true / false` | 右列“是 / 否” |
| `multi_branch` | 多分支 | `in / case:* / default` | 右列按 case 展开，默认端口使用菱形 |
| `loop` | 循环 | `in / loop_body / loop_complete` | 左列“进入循环”，右列“循环体 / 离开循环” |
| `break` | 跳出循环 | `in` | 终止当前循环路径的标记 |
| `continue` | 继续循环 | `in` | 下一轮迭代标记，不绘制回边 |
| `return` | 返回 | `in` | 终止节点，不连接 `exit` |

明确没有 `merge` 节点。汇合语义由多条边进入同一个目标节点表达。

## 4. 分支与汇入规则

- 分支的 continuing arm 直接连接到下一个真实语句；只有真实到达隐式结束时才连接到 `exit`。
- 同一条 target 节点可以接收多条不同 kind 的入边。
- 原始边的 `true / false / case / default / loop_body / loop_complete` 标签保留在边数据中；`break` / `continue` 是节点而不是边。
- 不生成边级悬浮胶囊；同样的文字由目标卡片内部端口行表达。
- 循环体末尾的隐式迭代不绘制回边；如果分支或内层循环在该位置没有可见目标，其端口仍保留，但可以不产生出边。
- 这是 P5“有界执行流”的边界，不得通过重新引入 `merge` 节点或 back lane 来补齐。

## 5. 签名与占位

执行流卡片不显示函数/方法签名。签名只保留在 FunctionDetail、Method Detail 和节点详情面板；卡片正文显示 label 与 human note，长 note 最多两行截断。

HTML 基准样例中的自由函数、功能接口和动态分发使用注释占位：

```text
# 本地调用人类备注占位
# 功能模块接口人类备注占位
# 动态分发边界说明占位
```

生产渲染使用 bundle 中的真实 `note`；签名不进入执行流卡片。

## 6. 边与锚点

- Python 布局层提供初始端口锚点。
- 浏览器渲染后按卡片内部真实 `.exec-port-item` 的行中心重新计算边锚点。
- 拖拽卡片时边会按内部端口重新路由。
- 边路径使用贝塞尔曲线；长距离的 loop complete 边使用 lane 绕行。
- 不允许执行边使用 `call` / `call_path` / `composition`。
- 实线只表示静态确定的直接控制/执行关系；虚线只表示推断、不完整或间接关系。
- `default` 等确定控制关系使用实线；`break` / `continue` 不生成出边，通过节点类型和端口表达。
- `return` 无出边，`exit` 无出边。
- `break` / `continue` 是循环体内终止标记，无出边；循环离开统一由 `loop_complete` 端口表达。

## 8. 验收要点

- 执行流 bundle 中不存在 `kind=merge` 节点。
- 所有节点均为封闭集合中的 11 种 kind。
- 卡片中包含内嵌端口，不存在 `.exec-port-dot`。
- 执行流不生成 `.exec-edge-capsule`。
- loop 端口集合为 `in / loop_body / loop_complete`。
- 多分支、dispatch、循环、终止节点均可正常渲染。
- 拖拽后边端点跟随内部端口行。
- build/check、全量测试和浏览器冒烟通过。
